Choros is now usable from a lot more places than the desktop app: a fleshed-out CLI and TypeScript SDK, a Slack agent that spins up workspaces on its own, and a mobile app heading into internal review.

## Automations

**Automations are cron jobs for agent sessions.** Pick a project, write a prompt, set a schedule, and Choros dispatches an agent run against a fresh workspace every time it fires. The output is a live workspace you can open, review, and continue interactively.

Typical uses:

- **Nightly standups**: summarize PRs, issues, and activity from the last 24 hours
- **Release notes**: draft from merged commits each week
- **Security & dependency sweeps**: scan for vulnerable packages or deprecated APIs every morning
- **Long-running refactors**: "bump TypeScript to 5.7 in the next un-migrated package" on a daily cadence

This batch brings automations into their own as a first-class workflow:

- **Prompt version history** <PRBadge url="https://github.com/superset-sh/choros/pull/3996" />: every edit to an automation's prompt is snapshotted. Browse previous versions and restore any of them, so an accidental change is no longer a one-way door.
- **Redesigned automations tab** <PRBadge url="https://github.com/superset-sh/choros/pull/4225" />: new layout that makes a queue of runs easier to scan at a glance.
- **Mine vs. Team filter** <PRBadge url="https://github.com/superset-sh/choros/pull/4403" />: automations now belong to a team. Filter the runs view between **Mine** and **Team** to see only what you ran vs. everything your team kicked off.

### Drive them from the CLI

Everything you can do in the UI is now scriptable. New in this batch: `prompt get` / `prompt set` <PRBadge url="https://github.com/superset-sh/choros/pull/3966" /> and the `--name` filter on list <PRBadge url="https://github.com/superset-sh/choros/pull/3959" />.

```bash
# create a recurring run from a prompt file
choros automations create \
  --name "Nightly audit" \
  --rrule "FREQ=DAILY;BYHOUR=3;BYMINUTE=0" \
  --project <projectId> \
  --agent claude \
  --prompt-file prompt.md

# manage the queue
choros automations list --name "Nightly"
choros automations pause <id>
choros automations resume <id>

# iterate on the prompt (backed by the new version history)
choros automations prompt get <id> > prompt.md
$EDITOR prompt.md
choros automations prompt set <id> --file prompt.md

# fire one off-schedule (also works from the SDK / Slack bot / MCP)
choros automations run <id>
```

`choros automations run` is also exposed via the **TypeScript SDK** and **MCP**, so you can dispatch runs from a CI job, an internal admin panel, or a Slack slash command. See the [Automations docs](https://docs.choros.sh/docs/automations) for the full surface.

## Choros CLI

The `choros` CLI grew real project and workspace commands and a cross-device login flow.

**New commands:**

- `choros projects create` <PRBadge url="https://github.com/superset-sh/choros/pull/4355" />: scaffold a new Choros project from your shell.
- `choros projects setup` <PRBadge url="https://github.com/superset-sh/choros/pull/4356" />: link an existing local repo to a Choros project.
- `choros workspaces open` <PRBadge url="https://github.com/superset-sh/choros/pull/4258" />: open a workspace directly from the terminal.
- `choros auth login` <PRBadge url="https://github.com/superset-sh/choros/pull/3965" />: now uses OAuth device code + PKCE, so it works on headless servers and across devices.

**Setting it up:**

```bash
# install
curl -fsSL https://choros.sh/cli/install.sh | sh
# or: brew install superset-sh/tap/choros
# or: it's already bundled with the desktop app at ~/.superset/bin/choros

# sign in (opens a browser, or prints a code for a second device)
choros auth login

# scaffold a project and open a workspace
choros projects create
choros workspaces open
```

The accompanying **TypeScript SDK** <PRBadge url="https://github.com/superset-sh/choros/pull/3937" /> (`@choros_sh/sdk`) mirrors the CLI 1:1 (same procedures, same shapes), so anything you can do from your shell, you can do from a script, a CI job, or an internal tool.

```bash
npm install @choros_sh/sdk
```

```ts
import Choros from '@choros_sh/sdk';
const client = new Choros(); // reads SUPERSET_API_KEY / SUPERSET_ORGANIZATION_ID
await client.automations.run('<automation-id>');
```

Linux `choros start` and `choros update` are now fixed <PRBadge url="https://github.com/superset-sh/choros/pull/4635" />.

## Slack bot

![Choros Slack bot spinning up a workspace and reporting back in-thread](/changelog/slack.png)

`@choros` in Slack is now an actual agent, not a task-filer. Mention it in a channel or DM it from anywhere, and it can:

- **Create, update, search, and triage tasks** from the conversation it's standing in, pulling assignees, statuses, and priorities from your team's Linear/Choros setup.
- **Spin up a cloud workspace and launch a coding agent** to actually do the work. For code-change requests (e.g. "@choros bump our Sentry SDK to v9 across all apps"), it now defaults to spawning a workspace and agent rather than just filing a ticket <PRBadge url="https://github.com/superset-sh/choros/pull/4660" />.
- **Read the thread or channel history** on its own to gather context: no need to copy-paste the prior messages.
- **Search the web with citations** when a request needs up-to-date info.
- **Unfurl Choros task and workspace links** with rich previews when they're shared in a channel.

**Setting it up:**

1. In the dashboard, go to **Integrations → Slack**.
2. Click **Connect** to install the Choros Slack app into your workspace (OAuth).
3. Mention `@choros` in any channel, or open a DM with the bot, and describe what you want done.

If Slack was already connected before this release, no action needed: proactive workspace creation is on by default.
