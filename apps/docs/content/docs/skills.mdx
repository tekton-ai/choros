Skills teach the coding agents you already use how to drive Choros: orchestrate parallel agents, create automations, diagnose problems, and more.

<YouTubeVideo id="8g-l5kYEGBc" title="Choros CLI + Skills Demo" thumbnail="/images/cli-skills-demo.jpg" />

## Installation

**Using the Choros desktop app?** Skills are already installed. The app provisions them at launch and keeps them updated.

Otherwise, install them directly:

```bash
npx skills add choros-sh/skills
```

Or, in Claude Code, via the plugin marketplace:

```text
/plugin marketplace add choros-sh/choros
```

## What You Get

| Skill | What it does |
|:------|:-------------|
| `choros:setup` | Makes a repo Choros-ready: authors `.choros/config.json` and project lifecycle scripts, then verifies with a real workspace |
| `choros:orchestrate` | Turns the agent you're talking to into a coordinator of parallel agents; see [Agent Orchestration](/orchestration) |
| `choros:automate` | Turns a recurring chore into a scheduled [automation](/automations) and reviews its first run with you |
| `choros:browser` | Drives a workspace's [in-app browser](/browser) panes — open, navigate, screenshot, eval, read console, and raw CDP for click/type automation — and routes to [Browser Use 3.0](/browser#browser-use-30) for browsers the panes can't reach |
| `choros:computer` | Drives [native desktop apps](/computer) through an accessibility-first driver (Cua Driver by default) — inspect windows, click, type, use menus, and verify results with background interaction when the platform supports it |
| `choros:standup` | Sweeps your workspaces, tasks, and agent terminals into a digest: what needs you, what's in flight, what's blocked |
| `choros:doctor` | Diagnoses Choros problems (expired auth, offline hosts, stale versions) and fixes them one step at a time |
| `choros:feedback` | Files a bug report or feature request: privately to the Choros team (from your account, so we can reply) or as a public GitHub issue |
| `choros:10x` | Audits how you use Choros and teaches the advanced features you're not using yet |
| `choros:contribute` | Sets up a Choros open-source contribution end to end, following the repo's contribution rules |

## Using Skills

You usually don't invoke them; agents pick the right skill from context:

- "report this bug to the choros team" → `choros:feedback`
- "what did my agents do overnight?" → `choros:standup`
- "run these three refactors in parallel" → `choros:orchestrate`
- "open localhost:3000 and click through the signup flow" → `choros:browser`
- "open the desktop app and change its settings" → `choros:computer`

To invoke one explicitly: `/choros:feedback` in Claude Code, or `/choros/feedback` in the in-app chat. Other agents that read skills (Codex, Kimi, Vibe, Grok) see the same skills with a `choros-` prefix.

## How They're Delivered

At launch, the desktop app writes managed copies into the standard discovery locations: `~/.claude/skills/choros/` (loaded by Claude Code as a plugin, hence the `choros:` namespace), `~/.agents/skills/`, and `~/.agents/commands/`.

- **Your files are never touched.** Managed files carry a marker; a skill or command you authored at the same path is left alone.
- **Updates are automatic.** Managed skills refresh on every app launch, and ones that no longer ship are cleaned up.
