# Intent — 官网产品化改版

## Problem

用户反馈现有官网“太随意了”，希望参考 https://superset.sh/ 的风格，但不能完全一样。当前官网首页与公共导航集中在 `apps/site/src/site.ts`：首屏为超大衬线标题和 CLI 示例，主行动是阅读文档，导航仅包含 Docs、Changelog、Status，没有下载入口。实际运行页面确认了这一信息结构。新访客无法直接看到桌面产品的工作方式，也缺乏清晰的下载路径。

用户在后续澄清中明确：“我们官网不需要做登录”。该决定替代最初的登录入口要求；本次不增加官网登录、账户页或认证流程。

## Proposed outcome

首次访问者能在首屏理解 Choros 是用于组织多个 coding agent 的桌面产品，能看到其真实工作界面，并找到可用的下载入口。已有用户能在桌面和手机访问官网时直接找到下载、文档和更新日志；官网保持公开访问，不要求登录。

官网呈现与参考站相近的克制、清晰、产品优先的视觉品质，同时仍可辨认为 Choros，而不是替换名称后的 Superset 页面。

## Affected users and systems

- 用户：首次了解 Choros 的开发者，以及希望下载或查阅文档的现有用户。
- 官网：`apps/site/src/site.ts` 的首页、共享导航和样式，以及 `apps/site/src/build.ts` 的静态发布边界。
- 认证与桌面端登录不在范围内，保持现有行为，不修改认证服务、会话或回调契约。

## Constraints

- 参考目标以用户提供的 https://superset.sh/ 为准。不复制对方的品牌标志、独有素材、文案、客户评价或客户背书。
- 保留 Choros 品牌识别及现有可用的文档、更新日志、法律页面和状态页路径。
- 只展示当前产品真实具备的能力；参考站存在的云端、远程、自动化、企业及计费能力不因此成为 Choros 的承诺。
- 保持已接受的本地产品边界；本次不增加云端工作区、组织、团队、计费或网页管理后台。
- 官网不提供登录入口、账户页或新增认证流程；下载与内容浏览不以登录为前提。
- 桌面和手机均需有清晰的导航与下载路径；键盘访问、可读性、减少动画偏好及现有国际化约定需在验收中覆盖。
- 本 intent 已由用户明确接受。按仓库 SDLC 规则，下一阶段为 spec；spec 和 plan 分别获得接受后才实施代码。本次没有修改官网或认证实现。

## Open questions

当前没有待用户决定的登录范围问题：官网不做登录。真实产品展示素材、下载目标及响应式验收细节在下一阶段 spec 中根据现有产品和发布配置明确。
