# Spec — Choros 官网产品化改版

前置条件：同目录 `intent.md` 已由用户在会话中明确接受，并记录为 `status: accepted`。用户在收到本规格及“接受后进入实施计划”的说明后回复“继续啊”，确认继续进入 plan；agent 记录该人类审批决定，不代为接受后续实施计划。

## Requirements & design spec

### Functional requirements

#### 1. 产品与范围

官网面向了解、下载和学习 Choros 的开发者，保持公开静态站点。首页应明确说明：Choros 是组织 coding agent 的桌面工作空间，支持在独立 Git worktree 中并行工作、查看进度与审查改动。

**官网不做登录。** 不添加登录、注册、账户、Dashboard 入口，不调用认证服务，不改变桌面端登录或回调契约。下载和文档不以登录为前提。

参考 https://superset.sh/ 的深色、清晰层级、细边框和产品优先的展示方式，但不复制其居中首屏布局、文字、动画、图像、用户评价或客户背书。

#### 2. 首页信息结构

桌面布局示意（非最终像素稿）：

```text
┌────────────────────────────────────────────────────────────────────┐
│ Choros                 Product   Docs   Changelog   [Download]      │
├────────────────────────────────────────────────────────────────────┤
│ THE WORKSPACE FOR CODING AGENTS                                     │
│ Your agents.                                                       │
│ One clear workspace.                                               │
│ 简洁说明并行 Agent、独立工作区和改动审查                              │
│ [Download Choros]     Explore the workflow ↓                        │
│                                                                    │
│ ┌──────────────── Choros 真实桌面界面 ────────────────────────────┐ │
│ │ 工作区列表             Agent / 终端                 改动审查    │ │
│ └────────────────────────────────────────────────────────────────┘ │
├────────────────────────────────────────────────────────────────────┤
│ 01 Run work in parallel          多个 Agent 的进度与后续操作          │
│ 02 Give each task its own space  独立分支与文件上下文                 │

├────────────────────────────────────────────────────────────────────┤

├────────────────────────────────────────────────────────────────────┤
│ Frequently asked questions                                         │

├────────────────────────────────────────────────────────────────────┤
│ Choros / Tekton AI       GitHub · Docs · Changelog · Status           │
│                                                   Terms · Privacy  │

```

- 页头与页脚复用已选定的 Choros 标志；不重新设计字标或三条 C 形弧线。
- 页头产品链接定位首页工作流区域；Docs 与 Changelog 保持现有页面；Download 定位首页下载区域。其他页面的产品/下载入口必须返回首页正确锚点。
- 首屏左对齐，桌面标题控制在两行左右；主行动为下载，次行动为了解工作流。以上英文标题为规格建议文案，不是测试需要锁死的字串。
- 产品实景放在首屏说明下方，成为最大视觉主体；不再用倾斜 CLI 面板代表整个桌面产品。
- 三段工作流采用连续的编辑式分区：编号、短标题、具体说明，配合相关实景局部。不是三张只有概念口号的卡片，也不引入需要 JavaScript 的轮播或自动切换演示。
- GitHub 放入页脚，不展示未经证实的 Star 数量、客户 Logo、评价、增长数字或“永久免费”等承诺。
- FAQ 使用原生可展开语义控件，键盘与无 JavaScript 情况下均可用。回答限定于已存在的桌面工作流，不承诺云端、远程、自动化、Windows 可用性或模型服务免费。
- 文档、更新日志、法律和状态页沿用正文内容与路径；仅统一公共导航、字体、间距和链接状态，不在此次改版重写法律文案或扩建文档系统。

#### 3. 视觉规范与差异化

沿用 `apps/site/src/site.ts` 的现有 CSS 变量名称和静态页面组织，不为样式重做建立第二套组件框架。视觉取值参考 `packages/ui/src/globals.css` 的深色中性色层级及 `docs/design/choros-identity-v1/README.md`：

| 元素 | 规格 |
| --- | --- |
| 品牌 | 深底白色标志，保持比例与弧线间距；可在背景使用低对比度的自有弧线装饰，不压住内容。 |
| 背景与面板 | 由当前偏棕/绿色背景调整为近黑中性色；主体可采用品牌文档中的 `#111113`，面板仅提高一级亮度。移除全页网格、明显光晕和倾斜投影。 |
| 正文与次要文字 | 近白正文、清晰灰色次要文字；复用共享深色主题的 foreground / muted-foreground 层级，不用低对比度灰字承载重要说明。 |
| 强调色 | 保留现有 `--acid: #d8ff3e`，仅用于编号、状态点或少量交互强调；标题不再大面积荧光绿。主下载按钮采用近白底、深色字。 |
| 字体 | 系统无衬线栈用于标题与正文；等宽字体仅用于技术标识、编号及代码。标志已有路径，不加载 Avenir 字体。无外部字体请求。 |
| 宽度与间距 | 延续 1180px 内容上限；桌面左右至少 32px 留白、移动端至少 20px；主分区桌面 88–112px、移动端 48–64px 垂直间距。 |
| 字号 | 桌面主标题约 64–80px、行高 1.04–1.12；手机约 40–48px、行高不低于 1.1；正文 16–20px。使用流式字号，不依赖硬编码换行适配手机。 |
| 边框与圆角 | 1px 低对比度边框；按钮小圆角，产品实景容器约 10px 圆角，与共享 UI 默认半径相近。不使用大面积胶囊卡片。 |
| 动效 | 仅短促的颜色/边框/位移反馈；内容默认可见，不依赖滚动动画解锁。减少动画偏好下禁用位移与平滑滚动。 |

区别来自 Choros 现有弧线标志、左对齐首屏、连续三段工作流及克制的绿色，而不是复刻 Superset 页面后替换名称。

#### 4. 产品图与品牌素材

- 品牌资产来源：`docs/design/choros-identity-v1/choros-logo-light.svg` 与同目录 mark 素材。现有首页内联标志也是同一身份资产，不另画近似图形。
- 当前已检索的设计素材只有品牌预览和桌面登录前后截图；登录截图不适合作为此次官网产品实景，不使用。
- **产品图必须在实施阶段从运行中的 Choros 捕获。** 使用专门的演示项目与工作区，执行真实的工作区/终端/改动查看操作；可使用合成项目数据，但不在 HTML 或图片中伪造不存在的产品控件。
- 主图展示工作区列表、Agent/终端和改动审查的实际关系；三段工作流可使用真实截图的相关裁切，不要求额外制作视频。
- 截图不得包含真实账号、邮箱、用户头像、私有仓库名、个人绝对路径、密钥、业务代码或本次会话。生成前使用无敏感信息的演示环境，发布前人工可视检查。
- 图片为站内静态资源，提供尺寸、响应式版本与有意义的替代文本；禁止热链参考站图像。移动端不能把整张宽桌面图压成不可读缩略图，采用保持同一真实内容的局部裁切与紧邻文字说明，并提供查看完整图的链接。
- 若实际运行环境无法取得合格截图，阻断最终页面验收并报告具体原因，不用旧 Superset 图、登录图、线框图或合成 UI 冒充完成。

#### 5. 下载路径与平台行为

官网提供明确的平台选择，不猜测 CPU 架构、不自动下载，也不因用户浏览器所在系统隐藏其他平台。页头和首屏 Download 均跳至首页下载区域；真正的安装包链接清楚标注平台与架构。

已通过未携带登录凭据的 GitHub API 确认当前正式发布为 `desktop-v0.1.2`，`draft=false`、`prerelease=false`。2026-09-07 对以下稳定下载 URL 发起 HEAD 请求，全部返回 200 且 Content-Disposition 为相应安装包：

| 显示平台 | 稳定下载 URL |
| --- | --- |
| macOS · Apple Silicon | https://github.com/tekton-ai/choros/releases/latest/download/Choros-arm64.dmg |
| macOS · Intel | https://github.com/tekton-ai/choros/releases/latest/download/Choros-x64.dmg |
| Linux · x86_64 | https://github.com/tekton-ai/choros/releases/latest/download/Choros-x86_64.AppImage |

- 全部版本链接为 https://github.com/tekton-ai/choros/releases/latest 。安装与首次使用帮助链接为现有文档入口。
- 不在页面中固定 `0.1.2` 为“最新版”，不在每次访问时调用 GitHub API；稳定资产命名由既有 release workflow 保持。
- 当前没有已发布的 Windows 安装包。即使打包配置中存在 Windows target，也不显示 Windows 下载按钮或“即将推出”的占位承诺。
- 手机显示同样的平台列表，并说明这是桌面应用，不提供假的 iOS/Android 下载。
- 下载是普通 HTTPS 导航，不执行 OAuth、不打开自定义协议、不使用代理传输安装包。GitHub 的源站失败应保留真实错误，不伪装为下载成功；下载区始终提供正式发布页链接。
- 本次核实只覆盖发布元数据与 HTTP 下载可达性，不代表重新验证了三个平台的安装及运行兼容性。

#### 6. 响应式、可访问性与国际化

- 桌面页头一行；窄屏采用“标志 + 下载按钮”首行及简短导航次行，不靠隐藏登录或多层菜单节省空间，不新增菜单脚本。
- 在 320、390、768、1440 CSS 像素宽度下无页面级横向溢出。文档代码块可以局部横向滚动。
- 下载按钮及主要触控入口至少 44 × 44 CSS 像素。提供明确的 hover、focus-visible 状态与跳至正文入口；粘性页头不得遮挡锚点目标或键盘焦点。
- 单一主标题、正确的标题层级、main/nav/footer 语义；装饰图形不重复进入读屏顺序。普通正文至少达到 WCAG AA 4.5:1 对比度，大文字至少 3:1。
- 放大到 200% 时核心内容与下载操作仍可达，不截断关键信息。FAQ 可通过 Tab、Enter/Space 操作。
- 本次保持现有官网默认英文及无语言切换器的路由行为，不扩展多语言网站导航。新写或改动的用户可见文案仍必须采用仓库规定的 Lingui 显式 ID，经现有非 React 入口在构建时生成，不新建硬编码文案表。
- 新增 message 使用 `site.*` 命名空间；已启用 locale 的新增消息需要按现有目录流程补全并通过 `bun run --cwd packages/i18n check`。不修改 `SUPPORTED_LOCALES`，也不为静态站向浏览器交付全量语言目录。

### Non-functional requirements

- 继续使用 Bun 生成静态 HTML 并发布到 GitHub Pages；无新增数据库、服务端 API、React/Next.js 应用、客户端路由或第三方 UI 框架。
- 核心文案、导航、FAQ、产品图与下载在禁用 JavaScript 时可用；不增加客户端脚本包、第三方字体、自动播放视频或统计 SDK。
- 新增首页媒体文件总量以不超过 1.5 MiB 为验收上限；首图不延迟加载，非首屏图片延迟加载，声明尺寸防止布局跳动。复用裁切素材时不重复嵌入大图 base64。
- 静态发布必须同时支持根目录部署与 `SITE_BASE_PATH=/choros`。页面链接、图片、srcset、完整图片入口和首页锚点均不能遗漏或重复前缀；外部 GitHub 下载 URL 保持不变。
- 本地请求处理仍保留现有安全响应头及真实 404；不得把 Bun Response 中的 HTTP 头误认为 GitHub Pages 自动提供相同保护。此次不引入需要该假设才能安全运行的脚本或敏感表单。
- 发布产物必须包含产品图与品牌资源，冷启动访问深层文档及不存在路径不依赖客户端路由。现有 10 条 canonical 页面路径与 3 条 redirect 契约保持不变。
- 新增共享 i18n 依赖后，静态站构建必须能在干净 CI 环境运行；部署触发范围必须覆盖会改变产物的共享目录/依赖，不能只在本机装有 node_modules 时成功。

### Acceptance criteria

1. **内容与品牌：** 首页呈现自有标志、左对齐产品主张、真实产品图、三段工作流、下载区和 FAQ；没有 Superset 的品牌素材、虚构背书或未实现能力承诺。
2. **无登录：** 官网所有新增导航和行动均指向公开内容或官方下载；浏览首页与下载流程不产生认证请求，不出现登录/注册/账户/Dashboard 入口；桌面认证实现没有变化。
3. **下载：** 三个平台/架构标签与稳定资产名称对应；从页头到平台安装包的路径可通过键盘和触摸完成，不需要自动系统识别。发布前再次检查下载 HEAD/重定向结果，不下载整套大型安装包来证明链接可达。
4. **布局与键盘：** 在上述四种宽度、200% 缩放和减少动画偏好下检查无关键遮挡；实际打开 FAQ、跳转产品及下载锚点，检查焦点可见与顺序。
5. **产品素材：** 提供实际运行 Choros 的截图来源、演示场景及发布前隐私检查结果；网页显示的裁切与原图一致，无私人信息。
6. **部署：** 根路径及 `/choros` 下，首页、代表性深层文档、所有静态图片、三个旧路径跳转和未知路径均保持正确；站内资源无 404，浏览器无新增资源/CSP/脚本错误。
7. **工程：** 保持站点现有路由行为验证，新增或修改的文案通过 i18n 检查；不为锁定具体标题、CSS 字符串或文件内容而新增快照测试。页面效果通过真实浏览器及桌面/手机截图验收，不能只以单元测试通过代替。

### Out of scope

- 官网登录、注册、账户页、认证、OAuth 或桌面协议接续。
- 网页工作区、Dashboard、云端/远程执行、自动化、团队、计费或新增后台。
- 桌面功能修改、发布新版本、调整打包矩阵、发布 Windows 包或验证所有平台的安装运行。
- 新标志、复制参考站素材、营销客户数据、虚构案例、追踪统计或邮件收集。
- 整站文档内容重写、搜索系统、多语言站点路由、语言切换器或法律条款重写。
- 自动部署或对线上站点直接写入；实现、构建和验证须在后续 plan 获得接受后进行。

## Integration with existing code

- `apps/site/src/site.ts`：`getPage` 负责首页与内容页面；`pageShell` 负责共享导航/页脚；`styles` 包含现有视觉变量；`handlePublicSiteRequest`、`PUBLIC_SITE_PATHS`、`PUBLIC_SITE_REDIRECTS` 提供需保持的 HTTP 路由契约。不另建平行站点。
- `apps/site/src/build.ts`：当前只输出 HTML 和重定向页，`withBasePath` 只处理 `href="/`。产品图与共享文案进入后，构建需要满足本规格中的资源完整性与 base-path 结果要求；具体代码分解属于 plan。
- `apps/site/src/dev.ts`：当前仅将请求交给页面处理器；实现后本地预览也需能够加载与正式产物相同的静态资源。
- `.github/workflows/deploy-pages.yml`：当前使用 `/choros` 前缀，构建前没有依赖安装步骤，触发范围也不含共享 i18n。新增构建期依赖必须与该发布边界一并处理。
- `docs/design/choros-identity-v1/README.md` 及对应 SVG：已确认的品牌资产来源；`packages/ui/src/globals.css` 提供可复用的暗色中性色层级，不为复用色值把整套 React/Tailwind 引入站点。
- `packages/i18n/README.md`、`packages/i18n/src/index.ts`、`packages/i18n/src/locales.ts` 与现有消息目录：使用非 React 翻译入口及显式 ID，保持默认英文静态行为；现有目录检查承担翻译完整性。
- `packages/i18n/lingui.config.ts`：当前提取目录没有包含 `apps/site/src`；新站点文案必须进入同一套 catalog 的提取范围，否则即使使用显式 ID 也不会被完整翻译和检查。根 `lingui.config.ts` 仅重导出此配置，不另建站点目录。
- `apps/desktop/electron-builder.ts`、`.github/workflows/release-desktop.yml`、`scripts/release/README.md`：提供官方下载仓库与稳定文件命名契约。本次消费现有发布，不修改发布逻辑。
- `apps/site/src/site.test.ts`：现有 HTTP 状态、公开跳转、安全头契约保持；涉及具体品牌大小写或标题字串的断言不作为新版视觉正确性的证明。

## Policy compliance

### Brand

已读取 `docs/design/choros-identity-v1/README.md` 与 redesign skill：黑底白色 C 形弧线是既定方向，深色标志按 `#FFFFFF` 使用，保持比例与间距；字标已转路径，无字体授权或远程字体加载需求。沿用现有绿色而非新造品牌色板。文案、留白与视觉规格为本次提案，需产品/设计负责人接受；不把参考站客户或评价当成 Choros 的资产。

### Security

没有检测到独立组织 security policy/skill；需技术负责人在规格/实现审查中确认静态资源、构建依赖和发布边界。此次不触及身份、会话、密钥或用户输入。只使用站内媒体和指向已验证发布仓库的 HTTPS 链接，不引入脚本、API 代理或表单。截图隐私检查是交付门槛；不能因官网无登录就公开桌面端用户数据。

### Compliance
